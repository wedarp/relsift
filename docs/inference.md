# 函数依赖推导与反模型

发现和推导回答两类问题。发现读取表快照，返回当前行中成立的最小依赖。`wedarp/relsift/inference` 接收一组声明的依赖，计算这些前提在逻辑上蕴含哪些结论。可以把人工确认的规则作为前提，也可以把快照规则作为实验前提。推导的结论继承前提的适用范围。使用截断的发现报告时，推导仅针对报告中提供的规则。

## 从两条规则推导

```sh
moon run examples/inference
```

示例声明 `{order_id, line_no} → product_id` 和 `product_id → product_name`。查询 `{order_id, line_no} → product_name` 得到两步证明。第一步用第 0 条前提得到 `product_id`，第二步用第 1 条前提得到 `product_name`。查询同一组合能否决定 `warehouse` 时，例子给出一个反模型，两行可以有相同订单、行号、商品和商品名，同时所属仓库不同。见 [完整源码](../examples/inference/main.mbt)。

## 输入和返回契约

- `theory(columns, rules)` 以非空、无重复的字符串列 ID 编译规则，每个 `Rule` 有单属性右侧。允许空左侧表示常量依赖。拒绝未知列、重复左侧列、平凡规则和重复前提。列 ID 按字面精确匹配。`rules()` 返回副本，前提索引始终对应编译时规则的原始顺序。
- `Theory::closure(seeds, limits?)` 求属性闭包。种子和可证属性按字面排序，证明步骤按推导顺序排列。每步持有前提索引和新增属性。`verify_trace` 按前提独立重放步骤，并核对返回属性。它只证明记录下来的推导有效，完整性需要检查搜索状态。
- `Theory::explain(result, target)` 从一份可复核的闭包记录提取目标所依赖的步骤。若目标是种子，返回空证明。若记录中没有目标，返回 `None`。证明选择由原始推导顺序决定，可能存在步数更少的其他证明。
- `Theory::implies(lhs, rhs, limits?)` 返回 `Entailed(proof)`、`Refuted(agreement)` 或 `Undetermined`。可分别用 `verify_entailment` 和 `verify_counterexample` 独立检查正反证据。`Entailed` 在部分状态下仍成立，因为已有证明。`Refuted` 只在闭包完成后产生。非法输入通过 `model.InputError` 报告。

## 算法和预算

编译阶段按列记录引用该列的前提。查询先将种子和常量依赖得出的属性入队，每取出一个新属性就更新相关前提尚缺的列数。计数首次到零时可以应用该前提。队列中的列和被触发的前提各访问一次，搜索工作量取决于模式大小、前提数量和被触及的左侧列引用数。最终对属性集合排序。编译结果可复用于多次查询。

若闭包不含目标，可构造两行。第一行在所有列取 `0`，第二行仅在闭包中的列取 `0`，其他列取 `1`。凡两行在前提左侧相等，该前提右侧也属于闭包，因而两行满足全部前提。它们在查询的左侧相等、右侧不同，足以反驳逻辑蕴含。`Refuted` 以相等列集合表示这两行，可用 `verify_counterexample` 逐条检查前提。反模型中的行是逻辑构造，业务表中可能从未出现。

闭包查询单独计费。`max_candidates` 限制前提触发次数，包含右侧已知的前提。`max_results` 限制新增属性数量，种子不占限额。`max_work` 覆盖查询初始化、队列访问和前提引用更新；种子与输出整理、证据提取和独立复核在计费之外。分区、缓存计数均为零，`max_lhs`、`max_ucc_width` 不限制推导所接受的前提宽度。`CompleteInDomain` 表示对这组前提的闭包已完成，`Partial` 表示保留已证属性及推导步骤。这些计数无法代替进程资源限额。
