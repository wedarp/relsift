# 表快照与输入契约

## 身份和值

`Table` 有非空表 ID、`Column` 的非空列 ID/显示名称及 `Row` 的非空行 ID。表内列 ID、显示名称、行 ID 分别不能重复。每行宽度必须严格等于列数。跨表发现要求表 ID 不重复。

构造器复制所有可变数组，按 ID 的精确字符串字典序排列列和行，并同步移动单元格。访问器返回副本。一个分区索引只属于一个不可变快照；复制记录必须分配不同的行 ID。不同 ID 的完全相同记录仍是两行。

单元格类型为 `String?`。`""`、`"01"`、`"1"`、`"A"`、`"a"`、`"é"` 与 `"é"` 保持各自字面值。没有去空格、类型推断、大小写折叠、Unicode 规范化或数据库排序规则。

| NULL 策略 | 行为 |
|---|---|
| `RejectNull` / JSON `reject` | 任何 NULL 使输入非法；默认策略 |
| `NullAsValue` / JSON `equal` | 所有 NULL 相等，且不等于任意字符串；NULL 作为一个不同值参与 FD、UCC、IND |

这些是二值相等语义，不冒充 SQL 三值逻辑。单列 IND 的两个表必须采用相同 NULL 策略。

## JSON 表封装，版本 1

```json
{
  "schema_version": 1,
  "null_policy": "equal",
  "tables": [{
    "id": "export",
    "columns": [{"id": "code", "name": "Code"}],
    "rows": [
      {"id": "source-1", "cells": [null]},
      {"id": "source-2", "cells": [""]}
    ]
  }]
}
```

所示字段均必需；对象的未知字段和重复 JSON 键拒绝。单元格只接受字符串或 JSON `null`，数字和布尔值拒绝。表集合按表 ID 字典序排列。允许零张表、零列表以及零行表，仍需完整声明模式。表 ID 的跨导出稳定性由调用者负责。

解析字符串入口上限为 8 Mi UTF-16 代码单元，JSON 嵌套深度上限为 64；CLI 对每个输入文件另设 8 MiB UTF-8 字节上限。文件以严格 UTF-8 解码，可有起始 BOM。该上限不等于解析后的内存上限。

## CSV 配置

CSV 第一条记录是表头，列 ID 等于原始表头文字，必须非空且无重复。CLI 用 `--table-id` 指定表 ID，默认 `table`。所有 CSV 单元格都是 `Some(String)`，包括空字段；不推断 NULL。

解析器固定使用逗号，接受 LF、CRLF 记录结尾、起始 BOM、双引号字段、引号内换行及双引号的双写转义。引号只能从字段起始处开启，关闭引号后只能跟分隔符、记录结束或输入结束。拒绝未关闭引号、未加引号字段中的引号、关闭引号后的字符、引号外的独立 CR、行宽错误和非法表头。不猜测方言，不补字段，不跳过空记录，不去重。这里声明的是已实现的 CSV 配置，不宣称覆盖所有 RFC 或厂商扩展。

行 ID 按数据记录序号生成 `r1`、`r2` 等。它不是物理行号：引号内可以换行。CSV 重排后重新导入会重新分配 ID，因此证据 ID 只对当前导入快照有效。需要跨导出追踪时使用显式 JSON 行 ID。关系集合不受单纯行重排影响。

空文件没有模式，因而拒绝；只有合法表头的文件表示有模式的空表。单列表中的空白记录表示一个空字符串单元格；最后一个记录分隔符不会额外产生一条记录。

## 退化输入

对有模式的空表和单行表，任意 `∅ → A` 成立；其他非空左侧对同一右侧不再最小。空集合具有唯一性，因此唯一的最小 UCC 为 `∅`。零列而有多行时不存在 UCC；零列且至多一行时最小 UCC 仍为 `∅`。

报告的 `degenerate` 标记提示空表/单行表，但不会改变这些定义。没有可删除列时，删除证据为空是正常边界，不表示证明缺失。

单列 IND 只比较不同值集合：空源集合包含于任意目标集合，非空源集合不包含于空目标集合。目标列空表时数学上唯一，但这不能证明目标存在可用业务键。重复整行不改变 FD，却会破坏所有 UCC；重复目标值不破坏 IND。
