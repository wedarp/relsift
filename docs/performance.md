# 可复现性能实验

执行：

```sh
moon run examples/performance --target native --release
```

生成器与计时均为 MoonBit，源码在 `examples/performance/main.mbt`。每组从种子 `20261120` 开始，采用 UInt32 LCG（乘数 1664525、增量 1013904223），右移 8 位后按所声明基数取余。指定重复周期为 5 的组，每遇到正行号且能被 5 整除就复制前一整行；程序另外计算实际不同整行数与重复率。

计时范围是对已经构造好的表快照调用 `discover`，包含编码、共享分区、FD/UCC 搜索和证据生成；不包含生成数据、构造初始快照、编译和 JSON 渲染。每组一次预热，随后独立调用七次，报告所有耗时和中位数。使用毫秒墙钟 `env.now`，分辨率较粗，会受调度、垃圾回收和其他进程影响。

## 2026-11-21 的局部优化复测

同一机器和工具链、同一生成器及预算。优化前为提交 `f56218e`；优化后 FD 使用已有分区内的稠密首行数组并缓存已完成证据查询，避免为判断失败总是构造联合分区。两次运行均各预热一次、测量七次；它们是先后运行，没有进行随机交替或统计显著性检验。

| 行数 / 列数 | 优化前 7 次毫秒 | 优化后 7 次毫秒 | 中位数前 → 后 |
| --- | --- | --- | --- |
| 1000 / 4 | 3,4,4,4,4,5,5 | 3,3,3,3,4,4,4 | 4 → 3 ms |
| 4000 / 6 | 62,63,64,65,70,70,85 | 42,43,43,43,45,46,47 | 65 → 43 ms |
| 10000 / 6 | 165,172,172,174,179,186,206 | 110,115,115,116,118,123,124 | 174 → 116 ms |

行数、实际基数、重复率、候选数、FD/UCC 数量及完成域均与上表一致。优化后工作单位分别为 24749、778044、1991234；新扫描方式与代表数组初始化的计费不同，操作数增加不等于墙钟更慢。此处没有测量峰值内存，不能把少构造联合分区解释为已证实的总内存下降。

这些结果只支持此次固定数据的实测比较，不保证其他数据、宿主或宽表获得相同比例改善。低毫秒组的变化尤其容易受到计时分辨率与调度影响。

## 2026-11-25 公开数据基准

数据来自 [Palmer Penguins v0.1.0](https://github.com/allisonhorst/palmerpenguins/tree/v0.1.0/inst/extdata)（CC0）与 [UCI Wine Quality](https://doi.org/10.24432/C56S3T)（CC BY 4.0）。从原站获取数据，文件保存在仓库外。脚本校验每份源文件的 SHA-256。企鹅数据按原样导入，`NA` 保留为普通字符串。葡萄酒数据只将分号分隔改为逗号，保留字面数值和重复行。

```sh
moon build cmd/relsift --target native --release
node examples/performance/datasets.mjs DATA_DIRECTORY [BASELINE_EXECUTABLE]
```

`DATA_DIRECTORY` 包含 [penguins.csv](https://raw.githubusercontent.com/allisonhorst/palmerpenguins/v0.1.0/inst/extdata/penguins.csv)，以及从 [Wine Quality 官方压缩包](https://archive.ics.uci.edu/static/public/186/wine+quality.zip) 解出的 `winequality-red.csv` 和 `winequality-white.csv`。当前脚本同时读取下节列出的 `abalone.data` 与 `iris.data`。可选参数为旧版原生 CLI 的绝对路径，本次使用 `a0f74b8`。脚本输出源文件及输入哈希、每列基数、重复数量、七次耗时、状态与工作单位。每组先预热一次，并检查重复执行的输出一致。

本次使用 Windows 10.0.19045、Intel Core i7-9700、Node v24.19.0 和相同的 MoonBit 固定工具链。计时覆盖启动进程、读取文件、计算及 JSON 输出。发现宽度上限均为 4，发现和回归分别限制为 1 亿工作单位。三组发现均在声明域内完成。

| 数据 | 行 × 列 | 重复整行数 | FD / UCC | 发现中位数 | 新版回归中位数 | 旧版回归中位数 | 旧版 → 新版完成规则数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 企鹅 | 344 × 8 | 0 | 25 / 7 | 43.386 ms | 45.529 ms | 65.791 ms | 32 → 32 |
| 红葡萄酒 | 1599 × 12 | 240 | 782 / 0 | 455.094 ms | 2521.686 ms | 1050.756 ms | 25 → 782 |

回归用发现报告检查同一快照，覆盖大量仍成立的规则。旧版两组葡萄酒回归均在 `max_work` 耗尽时停止，耗时对应部分结果。脚本逐项核对旧版已完成的规则和新版对应前缀。新版三组回归消耗分别为 184034、26140884、19184544 个工作单位。计费随算法更新而变化。宽度四下观察到的葡萄酒函数依赖仍需要业务解释。

沿用上述环境、预算和计时方法。五组的发现与 0.2.1 回归均在声明域内完成，旧版已输出的回归记录与新版前缀一致。表内为七次测量的中位数。

## 0.4.0 宽表与声明规则基准

`moon run examples/performance --target native --release` 增加两组 256 行的合成宽表。两组使用种子 `20261120`，每列实际基数均为 32，重复整行为零，FD 左侧与 UCC 宽度均限制为三。沿用上述 Windows 环境，一次预热后测七次。脚本核对每次结果和证据一致。

| 列数 | 工作预算 | 实际工作单位 | 候选数 | FD / UCC | 状态 | 7 次毫秒耗时（升序） | 中位数 |
| ---: | ---: | ---: | ---: | ---: | --- | --- | ---: |
| 16 | 100000000 | 1245979 | 9913 | 1882 / 149 | 声明域内完成 | 30,30,31,31,32,32,33 | 31 ms |
| 24 | 2000000 | 2000000 | 6880 | 859 / 0 | 部分结果 | 32,32,33,33,33,33,34 | 33 ms |

24 列组特意使用较小预算。耗尽预算时仍处于 FD 搜索，零 UCC 表示尚未产生结果。

同一命令还构造 64 列、476 条声明规则。每列决定其后的最多八列，这组规则可精简为 63 条相邻列依赖。编译和样本构造均在计时之外。七次覆盖生成的耗时为 1,1,1,2,2,2,2 ms，七次独立审查的耗时为 0,0,1,1,1,1,1 ms。生成和审查分别使用 541522、126249 个工作单位。0 ms 表示低于计时分辨率。此组实验衡量规则集运算，仍需单独测量更大数据或不同形状规则下的峰值内存和耗时。
