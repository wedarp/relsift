# 发现算法与资源边界

## 共享分区

每列用 `Map[String?, Int32]` 进行字典编码。键相等由实际 `Eq` 判断，哈希碰撞不会被当作相等；NULL 与文本使用带类型的不同键。

列集合 `X` 的分区记录每行的等价类编号，完整保留单例与重复行。`X∪{A}` 由 `X` 的类编号与 `A` 的编码值构成二元组，在 `Map[(Int32,Int32),Int32]` 中求交。没有字符串分隔符拼接，也没有只比较摘要。缓存键是复制后的有序列位置数组，调用者不能修改缓存中的键或类数组。

空集合分区在非空表中有一个类，空表中有零个类。`X → A` 成立当且仅当 `π(X)` 与 `π(X∪{A})` 的类数相同。`X` 唯一当且仅当类数等于原始行数。

对已缓存分区，查找仍需集合键比较；新分区通常扫描全部行。内存包括原始字符串快照、编码列和已访问集合的分区，并非外部内存实现。

## FD 和 UCC

搜索按集合宽度递增，以惰性组合遍历器枚举候选，不预先分配整个幂集。FD 右侧仅为一个不在左侧的属性。空左侧被枚举，因此常量依赖不会遗漏。

对固定右侧，已发现的最小左侧剪去其超集；已发现 UCC 同样剪去其超集。候选成立后，从左侧删去每一列，利用父分区寻找失败行对。父分区中只需记录每类的首行，随后遇到不同右侧值即可构成 FD 反例；UCC 则返回同类的两个不同行 ID。

只在所有删除证据齐备且结果预算允许后发布结果。任意一步预算耗尽，尚在构造的结果被丢弃，先前输出仍成立且已证明左侧最小。由成立性质对超集的单调性，所有单列删除均失败足以证明不存在更小成立子集。

这里的左侧最小 FD 集合不等于全局最小覆盖；可能存在通过其他依赖推导的冗余规则，第一版不会将两者混称。

## 单列 IND

按表 ID、列 ID 顺序为每列建立不同值字典，以及按稳定行 ID 首次遇到的值序列。枚举不同表之间的有向列对，以基数先行排除不可能包含的候选，再扫描源值序列进行成员检查。成功候选报告两侧不同值数量和目标唯一性；失败列对不存入输出。

IND 没有声明目标主键要求，目标重复只改变 `target_unique`。第一版不声称复合外键发现。偶然相同的代码域也可能满足包含，必须人工复核含义。

## 独立验证

`verify.fd`、`verify.unique` 直接枚举行对并比较原始单元格。`verify.inclusion` 以数组去重、数组成员查询作集合参考，不复用生产索引。`verify_fd`、`verify_ucc` 还检查每个删除列恰好出现一次、行 ID 存在且不同、实际值构成所声明反例。

参考验证器可在大表上呈二次复杂度，其调用不受生产发现预算计数控制；调用者应选择合适的小表或独立的宿主资源限制。证据复核证明的是给定快照内的值关系，不是密码学来源认证。

## 搜索域与预算

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `max_lhs` | 4 | FD 左侧最大宽度 |
| `max_ucc_width` | 4 | 唯一组合最大宽度 |
| `max_candidates` | 100000 | 已考察的规则/唯一集合/跨表列对候选上限 |
| `max_work` | 10000000 | 结构工作量计数上限，Int64 |
| `max_results` | 10000 | 完整证明后发布的关系数量上限 |

负数预算非法，零预算合法。宽度与列数取较小值；FD 左侧还排除其右侧。候选数量包含已访问后被剪枝的候选。工作量在快照复制/编码准备、编码单元、分区键访问、求交行扫描、证据行扫描、组合遍历节点、剪枝检查以及 IND 列对和值检查处计费。计数检查先于相应工作；失败的收费不增加实际消耗。

该计数是公开的结构工作单位，**不是每次底层字符串比较、分配或哈希指令的精确数量**。输入构造、排序、解析、JSON 渲染以及独立验证不在生产搜索计数中。长字符串成本、临时对象、垃圾回收和系统调度仍会影响实际内存与耗时。没有硬内存或 CPU 隔离。

一个 `discover` 调用中 FD、UCC 共享同一个索引和总预算，FD 先执行；预算提前耗尽时可能尚未开始 UCC。`fd_complete`、`ucc_complete` 分别说明是否走完各自声明域。CLI 多表 `discover` 对每表独立应用同一组预算；IND 对整个表集合使用一份预算。

最坏候选规模仍与列子集数指数相关。缓存可避免重复求交，不能消除宽表搜索的组合爆炸。`complete_in_domain` 只对本次宽度与表集合定义的域作承诺；任何 `partial` 空结果都不能当作不存在关系。
